## 主要调用链

```text
main → Jenny → InitScreen
  → methods.init / getStartupImagePath / init2
  → initConfigs → 登录、网络、阅读器、下载与同步等设置
  → 解锁页 / 身份验证页 / 首次登录页 / AppScreen

业务页面 → Methods → MethodChannel("methods")
  → invoke({method, params}) → 各平台桥接 → Rust 核心
  → JSON 响应 → errorMessage / responseData → 数据模型 → UI
```

`Methods._invoke` 将非字符串参数编码为 JSON 字符串，再编码外层请求；响应错误通过 `StateError` 上抛，`responseData` 由业务方法继续解析，修改任一层格式都会影响原生核心兼容性。

平台入口分别为 Android 的 `MainActivity.kt` 与 `Jni.java`、iOS 的 `AppDelegate.swift`、macOS 的 `MainFlutterWindow.swift`、Windows/Linux 的 `methods_plugin`，以及 OpenHarmony 的 `EntryAbility.ets`；这些文件连接原生库，不能仅靠 Flutter 源码完成真实业务验收。

图片提供器先调用核心获得本地文件路径，再读文件解码；阅读器处理章节、方向、翻页、缩放和预加载，在线与下载资源的实际获取、存储和失败行为仍需核心源码与运行测试确认。

## 关键外部依赖

CI 将 `niuhuan/jasmine-rs-core` 检出到 `native/`，使用其中 `jmbackend/platforms/<平台>/Cargo.toml` 构建库并生成头文件；本次检出没有 `native/` 或 Cargo 清单，因此无法验证数据库、网络重试、缓存淘汰或下载调度实现。

业务依赖远端漫画 API/CDN，WebDAV 依赖用户配置的服务，生产构建还依赖平台 SDK、签名和核心仓库访问权限；这些依赖的可用性未进行联网或真实账号验证。

## 已观察到的缺口与风险

以下为静态阅读结果及待验证项，不替代人工触发的完整 Review，待办状态统一维护在 [feature.md](../feature.md)。

| 事项 | 源码依据 | 影响与后续验证 |
| --- | --- | --- |
| 构建环境未就绪 | 当前 shell 未找到 `flutter`、`dart`、`fvm`、`cargo`，本地缺少 `native/` | 本次没有执行应用测试、静态分析或生产构建，不能确认能运行 |
| SDK 与工具链待对齐 | `.fvmrc` 指向 Flutter 3.29.3，`pubspec.yaml` 仍限制 Dart `<3.0.0`；Build 与 Release 的 Rust/NDK 版本不同 | 需核验实际 SDK 和依赖解析结果，单独确认调整方案 |
| Flutter 测试与当前界面不符 | `test/widget_test.dart` 渲染空 `MaterialApp` 后断言计数器和加号 | 静态看测试无法验证现有应用；尚未实跑，不记为已执行失败 |
| OpenHarmony 测试仅验证字符串 | `Ability.test.ets` 的 `abc` 包含 `b` 断言 | 没有实际业务链路覆盖 |
| CI 缺少完整快速门禁 | 四个工作流均为 `workflow_dispatch`，未找到格式、analyze、test、Clippy 步骤 | 手动构建成功不能替代合并和推送门禁 |
| 发布流程与规范有差距 | `Release.yml` 使用 `gh release create --target`，发布工作流使用 `--clobber` | 需要 Tag 触发、不可覆盖制品及主分支一致性检查，改造前不应执行发布 |
| 原生并发容量待验证 | Android 使用 `newCachedThreadPool`，Apple 桥接创建 `Thread`，Windows 创建 `std::thread` | 需评估调用风暴下的线程和队列上限、过载退化及尾延迟 |
| OpenHarmony 参数日志存在敏感信息风险 | `EntryAbility.ets` 记录完整 `call.args`，登录与 WebDAV 请求可包含密码 | 后续需单独评审脱敏或删除参数日志并验证日志内容，本次未改代码 |
| 依赖与制品可复现性不足 | `.gitignore` 忽略 Dart/Rust 锁文件，核心检出未指定 `ref`，部分容器使用 `latest` | 需确认版本锁定和制品溯源方案，不能仅根据客户端 SHA 重建相同制品 |
| 版本资源由构建步骤提供 | `versions.dart` 读取 `lib/assets/version.txt`，该文件被忽略且当前不存在 | 本地构建须按 CI 从 `ci/version.code.txt` 准备资源 |
