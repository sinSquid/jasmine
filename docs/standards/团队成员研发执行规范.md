# 团队成员与 AI 协作执行规范

> 本文是[《团队与 AI Coding 项目规范》](<团队与AI Coding项目规范.md>)的人员执行入口，用于明确人在与 AI 协作时必须说清、评审和授权的事项。
>
> AI 可以分析、设计、编码和测试，但不能代替人确认需求、批准方案、接受风险或授权高风险操作。

## 1. 人必须承担的责任

- 向 AI 说明需求，并确认 AI 对需求的理解正确。
- 评审 AI 提供的技术方案，明确判断它是否与需求一致。
- 在 AI 开始开发、变更方案或执行受控操作前给出明确授权。
- 审查 AI 的实际改动、测试证据、未完成项和残余风险。
- 沉默、继续讨论、提问或只确认局部内容，都不代表授权 AI 进入下一阶段。

## 2. 发起任务：先对齐需求

人应向 AI 说明：

- 目标和验收标准；
- 实施范围和非目标；
- 兼容性、时间、性能或安全约束；
- 当前阶段仅允许 AI 分析和设计；完成方案评审并明确授权前不得开始实现。

在开始实现前，先要求 AI 复述需求、指出歧义和缺失，并给出它对范围与非目标的理解。有歧义时由人做出选择，不得让 AI 自行猜测。

建议用语：

> 我要做【XXX】需求。先不要改代码，请先了解现状，有不明确的地方先问我；需求对齐后输出一版简洁、完整的技术方案，等我确认后再开始开发。

## 3. 开发门禁：评审并确认 AI 方案

要求 AI 输出方案：

> 基于上述沟通，重新出一版完整方案，方案描述尽量简洁。

人必须评审方案，并确认：

- 满足需求和验收标准；
- 实施范围、影响范围和非目标清楚，没有夹带无关改动；
- 已考虑项目 `AGENTS.md`、团队门禁和必要约束；
- 测试计划覆盖自动测试、单元测试及其他适用的验证；
- 风险和需要人工决定的事项清楚。

只有人明确说明“方案与需求一致，可以开始开发”，AI 才能开始修改实现、依赖和配置。

确认开始开发：

> 方案与需求一致，可以开始开发，不得超出范围。

## 4. 开发中：处理偏离和新问题

发现实现偏离方案、扩大范围、增加依赖、修改配置或进行额外重构时，人必须要求 AI 停止，并确认偏离原因、影响范围、风险和验证方式。重新评审并明确同意后才能继续；与当前需求无关的问题不得顺手修改。

建议用语：

> 先停止实现。请说明偏离、影响和风险，等待我重新确认。

## 5. 开发后：触发 Review 并确认结果

实现完成后，人必须明确要求 AI 停止继续实现，进入 Review 阶段。Review 必须基于实际代码差异，不能只根据方案或交付总结。

人必须确认 AI 已认真完成 Review，并覆盖：

- 已确认的需求和技术方案；
- 项目 `AGENTS.md` 与团队门禁；
- 实际改动及影响范围，没有夹带无关修改；
- 自动测试、单元测试及其他适用测试是否已补充并实际执行；
- 测试结果、未验证项和缺失测试；
- `feature.md` 和其他必要文档；
- 已发现问题和残余风险。

人必须核对实际差异和测试证据，并根据 Review 结论决定修复、阻断或接受风险，不能只根据 AI 的总结判断已完成。修复后应重新触发 Review；未处理的问题必须明确记录原因和残余风险。AI Review 不能替代非作者人工评审。

建议用语：

> 进入 Review，先不要修改。请确认改动符合需求、方案、AGENTS.md 和门禁，检查自动测试、单元测试及执行结果，并说明影响范围、未验证项和风险。

## 6. 为操作单独授权

分析、修改、提交、推送、创建 Tag、发布和回滚是不同操作。人对前一操作的授权不代表后续操作也已获得授权。

| 操作        | 人必须说清的内容                |
| --------- | ----------------------- |
| 开始开发      | 明确确认方案与需求一致，并允许开始实现     |
| Git 提交    | 明确允许提交，并说明允许提交的变更范围     |
| Git 推送    | 明确允许推送，并指定目标远端和分支       |
| 创建或推送 Tag | 明确 Tag 名称和目标 Commit     |
| 发布或回滚     | 明确目标环境、制品、观察人、停止条件和回滚方式 |
| 高风险操作     | 由有权负责人明确批准具体操作、对象和范围    |
